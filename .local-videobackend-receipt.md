## What changed

Video attachments now work end to end. The catalog and cache already accepted a
`"video"` input modality, but every discovery backend narrowed a provider's
advertised `input_modalities` down to `text|image` **before** a `Model` existed,
so no model could ever carry `"video"` and the earlier cache fix had nothing to
act on. This lane made the producer side carry it.

**26 tracked files modified. 251 insertions, 71 deletions.** Of those, 23 are
this lane's; 3 belong to other lanes and were left exactly as found.

### The attachment-path defect
`coding-agent/src/tools/read.ts:1139` gated video reads on `input.includes("image")`
alone, so a model carrying `video` had its clip **silently degraded to a
metadata-only text block**. Now honours `video`.

both asserted `["text","image"]` for rows whose own fixtures advertise
`["text","image","video"]`. Both re-asserted against the real backends first.

## How it was verified

A throwaway harness under `/tmp` (nothing added to the repo) drove the **real**
paths with a real 3s h264+aac mp4:

- `file-processor.processFileArguments` accepted the file — 1 attachment, 12-frame
  4×3 PNG contact sheet, no `(skipped:` rejection
- real Novita backend on the repo's own live payload → `Model.input = ["text","image","video"]`
- outgoing body captured from `streamOpenAICompletions`:
  `POST …/chat/completions`, `model:"moonshotai/kimi-k2.7-code"`, parts
  `[{type:text},{type:image_url, data:image/png;base64,…}]`
- cache write→read round-trip with `bun:sqlite` instrumented: re-read returned
  `["text","image","video"]`, **provider-scoped purges `[]`**, row survived on disk.
  *Control:* a row with the unknown modality `"audio"` **is** a cache miss with
  purges `[]` — so the strict pass is still active and the `video` acceptance is
  real, not pass-everything.
- regression: text → string body / `[{type:text}]`; image → `image_url` intact;
  the video model still carries `text` **and** `image`.

Result: **ALL CHECKS PASS**, re-run green on the final tree.
